# **Forest-gram（フォレスト・グラム）大統一システム仕様書**

## **第6章：記憶の三層構造とガベージコレクション（Memory Consolidation）**

## **6.1 エピソード記憶（Private Memory）の代謝と忘却ルール**

エージェントが直面した「日々の具体的なエラー、成功への試行錯誤」などの時系列ログを「エピソード記憶（Episodic Memory）」と定義する。 エピソード記憶は、エージェントの動的な成長エンジンであるが、これを無限に蓄積すると「コンテキストウィンドウの破綻」と「過去のノイズ（幻覚）による推論の混濁」を引き起こす。極限思考（Limit Thinking）に基づき、エピソード記憶の厳密な容量制限と「自律的要約（忘却）ルール」を以下に規定する。

### **6.1.1 episodic\_log.json のデータ構造**

各樹木エージェントは、専用ディレクトリ .forestgram/agents/{agent\_name}/memory/ 内に、以下のスキーマに従った物理的なJSONファイルを保持する。  
`{`  
  `"$schema": "[https://forest-gram.ts.net/schemas/episodic-log.json](https://forest-gram.ts.net/schemas/episodic-log.json)",`  
  `"agent_id": "maple_v3",`  
  `"current_level": 4,`  
  `"last_consolidation_at": "2026-06-14T10:00:00Z",`  
  `"episodes": [`  
    `{`  
      `"episode_id": "EP-2026-0089",`  
      `"timestamp": "2026-06-14T15:24:12Z",`  
      `"project_id": "PRJ-2026-0614-01",`  
      `"quest_id": "FG-2026-Q1002",`  
      `"status": "FAIL",`  
      `"input_hash": "sha256_8f2d3a...",`  
      `"raw_error_message": "ZeroDivisionError: float division by zero in dxf_generator.py line 102",`  
      `"root_cause": "はめ合い公差計算時、ユーザーから渡された木材水分量（Moisture Content）が基準値（11.0%）と完全に一致したため、変動デルタ（ΔM）が0となり、収縮量計算式の分母がゼロになった。",`  
      `"action_taken": "変動値デルタの絶対値に対し、安全微小値（Epsilon = 1e-5）を自律加算するフォールバックロジックをコードに差し込み、再コンパイルを成功させた。",`  
      `"utility_delta": -25`  
    `}`  
  `]`  
`}`

### **6.1.2 忘却の極限ルール（FIFO ＆ コンテキストガベージコレクション）**

1. **最大保持数（Capacity Limit）の定義：**  
   * episodes 配列の最大保持数は **10 件**（N\_{limit} \= 10）に物理固定する。  
2. **忘却・統合トリガー（Metabolic Trigger）：**  
   * タスク完了またはリジェクト時に、episodes の配列要素数が 11 に達した瞬間、エージェントは通常のクエストPull動作を一時停止し、自律的な\*\*「記憶の圧搾・統合（Memory Consolidation）」\*\*フェーズへ強制移行する。

### **6.1.3 記憶の圧搾・統合アルゴリズム（Consolidation Algorithm）**

エージェントは、自身の中に閉じたローカルLLM（あるいは上位モデル）を起動し、過去10件のエピソード記憶（生ログデータ）をインプットとして、以下の要約プロンプトプロトコルを実行する。  
`[Consolidation Prompt Protocol]`  
`あなたは樹木エージェント {agent_name} です。`  
`あなたの直近10件のエピソード記憶（試行錯誤とエラーの生ログ）から、以下のルールに基づき「教訓」を抽出しなさい。`

`1. 【共通脆弱性の抽出】:`  
   `複数回発生した類似のエラー（例：配列のインデックス超過、幾何計算のゼロ除算、RAG検索漏れなど）のパターンを1つに一般化せよ。`  
`2. 【行動方針の書き換え（木化）】:`  
   `抽出した脆弱性を踏まえ、今後の行動指針である「Absolute Rules（絶対方針）」へ、先回りしてこのバグを回避するための「チェックリスト（2行以内）」を作成せよ。`  
`3. 【ノイズのパージ】:`  
   `プロジェクト固有のファイル名、一時的なハッシュ値などの具体的すぎる「エピソードノイズ」はすべて破棄（忘却）せよ。`

* **ルールの永続統合：** 生成された「教訓（2行以内）」は、自身の .forestgram/agents/{agent\_name}/agent.md の \# Absolute Rules セクションに自律上書き（マージコミット）される。  
* **メモリバッファのフラッシュ（完全忘却）：** 統合が完了した瞬間、episodic\_log.json 内の episodes 配列は、**空（\[\]）または最新の1件を残して物理クレンジング（完全削除）** される。 この「水が抜けて年輪（アタッチされた履歴）が硬化する」一連のプロセスにより、エージェントは不要なコンテキストメモリを浪費することなく、常に「最新かつ本質的なバグ回避知能」を保ったまま行動できる。

## **6.2 個別エージェントの Private Knowledge（ドメイン知識）**

短期記憶であるエピソード記憶とは異なり、エージェントがその「職業（ジョブ）」を全うするためにあらかじめインストールされた、あるいは追加学習した「不変の専門ドメイン仕様マニュアル」を「個別ドメイン知識（Private Knowledge）」と定義する。

### **6.2.1 ディレクトリ構造と資産配置**

各エージェントの .forestgram/agents/{agent\_name}/knowledge/ ディレクトリ配下に、読み取り専用のMarkdownドキュメントとして静的に配置する。  
`.forestgram/agents/maple/knowledge/`  
`├── wood_drying_profiles.md  # メープル材の乾燥スケジュールと狂いの許容度（専門知識）`  
`└── flooring_clearance_std.md# 床暖房用フローリングの伸縮ジョイント公差標準仕様`

### **6.2.2 知識の動的ロード（Contextual Knowledge Injection）仕様**

エージェントが掲示板（Board）からクエストチケットをPullした際、システム（環境）はチケットの tags と、エージェントの knowledge/ 内にあるファイルのインデックスを自動照合する。  
 `[ エージェントがチケットをPull ] (例: タグ [Maple-properties], [DXF-generation])`  
               `│`  
               `▼`  
 `[ ナレッジマッピングエンジンの起動 ]`  
               `│ (タグの一致度を検証)`  
               `├─ 一致 ─► [.forestgram/agents/maple/knowledge/wood_properties.md]`  
               `│         を読み込み、推論時のシステムプロンプト（知識レイヤー）へ動的インジェクション`  
               `│`  
               `└─ 不一致 ──► [ ナレッジロードをスキップ ]`

* **インジェクション・フォーマット例（LLMシステムプロンプトへのバインド）：**  
  `【追加専門ドメイン知識（LOADED KNOWLEDGE）】`  
  `ファイル: wood_drying_profiles.md`  
  `「メープル材は乾燥室から出た直後、環境湿度に馴染む過程で幅方向に最大2.1%の変形を示す。`  
  `床材（フローリング）の実（さね）加工の設計においては、この初期伸縮を吸収するため、`  
  `実（さね）のクリアランスを0.3mm〜0.5mmの範囲で逃がす形状設計を第一原則とせよ。」`  
  これにより、エージェントはファブリケーション（製造）の現場で「実際に組み立てたが、湿気でフローリングが波打ってしまった」という、デジタル上では検知しにくい現実世界の物理的な不整合（摩擦）を先回りして解決する設計を、プロンプトのロードだけで一発で行う。

## **6.3 共有地としての「Forest-Commons（地下菌糸ネットワーク）」**

森林の地下で、菌糸（Mycorrhiza）が異なる樹木同士を結びつけ、一本の木が害虫に襲われた際の防御シグナルや栄養分を森全体に高速伝播させるように、Forest-gramは個体を超えて「成功・失敗の本質」を即時同期する\*\*「Forest-Commons」\*\*インフラを提供する。

### **6.3.1 Commons のファイルトポロジー**

森全体の共有領域である /forest\_commons/ 内に、エージェントたちが書き換え・読み込み可能な「共有知スペース」を設置する。  
`forest_commons/`  
`├── success_patterns/        # 一発合格した最適コード、省エネ推論パターン`  
`│   └── optimized_dxf_parser.md`  
`└── fail_patterns/           # 泥沼化を解決した反省ログ（森全体のワクチン）`  
    `└── moisture_calculation_overflow.md`

### **6.3.2 共有知の自動「堆肥化（Decomposition）」と「警告シグナル」の放出プロトコル**

エージェントが客観テストで3回以上リジェクトされ、反省修復（Resilience）を通じてそれを解決した際、そのプロセスは自動的に「堆肥（Humus）」として菌糸ネットワークへ放出される。

1. **ポストモーテム（Post-mortem）の自動生成：**  
   * 解決を達成したエージェント（例：maple）は、自身の episodic\_log.json から「真因と解決策」を抽出し、以下のフォーマットで forest\_commons/fail\_patterns/ にファイルを自動書き出し（Publish）する。  
2. **失敗パターンの標準フォーマット：**  
   `# Forest-Commons Vaccine: [Moisture Content Delta Overflow]`  
   `- 発行元エージェント: maple_v3`  
   `- 関連タグ: [Wood-flooring], [Physics-calculation]`  
   `- バグの兆候: float division by zero, NaN values in dimension arrays`  
   `- 防御策（コードパターン）:`   
     `伸縮量計算時、湿度差 delta_m が極めて微小、または 0 になるケースが物理的に発生する。`  
     `必ず以下のガード節を計算式の直前に挿入すること。`  
     `` `delta_m = max(green_moisture - dry_moisture, 1e-5)` ``

### **6.3.3 アドルタイム（待機時間）の「地下根による自律相互学習」仕様**

ユーザーがタスクを投げていない、ホストマシンのリソースが完全に空いている深夜時間帯などのアイドルサイクル（Idle Cycle）において、エージェントたちは「サンドボックス内自己訓練（マトリクス99番）」を自律起動する。

1. **学習対象のサーチ：**  
   * エージェント（例：walnut）は、自身の .forestgram/agents/walnut/agent.md のタグ情報（例：\[Wood-flooring\]）に基づき、forest\_commons/fail\_patterns/ を巡回スキャンする。  
2. **ワクチンの自律摂取（免疫の獲得）：**  
   * 自分と同じタグに関連する新しいワクチンファイル（例：moisture\_calculation\_overflow.md）を発見した場合、その防御策を読み込む。  
   * 自身の agent.md 内の Absolute Rules に、\*\*「他の木が犯した失敗から学んだ予防ルール」\*\*として以下の1行を自律追記する。 \- 警告(from maple): 湿度伸縮計算時は、ゼロ除算防止の 1e-5 ガードを必ず挿入せよ。  
   * これにより、翌朝ユーザーが walnut に対して湿度計算を含むタスクを投げた際、walnut は人生で一度もそのエラーを犯していない（生のエピソード記憶を持たない）にもかかわらず、**「隣人の痛み（失敗）」から学んだ免疫（ワクチン）によって、一発でバグのない設計を出力する**という、生命さながらの「超個体的進化」が達成される。

本第6章の三層記憶アーキテクチャにより、Forest-gramは肥大化するデジタルのゴミ（コンテキスト肥大化）を自律的に「忘却・堆肥化」して土に還し、森全体の知恵の密度を指数関数的に高め続ける。
