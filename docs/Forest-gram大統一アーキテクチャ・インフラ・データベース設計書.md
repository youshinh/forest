# **Forest-gram（フォレスト・グラム）大統一アーキテクチャ設計書**

## **〜 用語定義・DBスキーマ・項目定義・インフラ構成・ネットワークトポロジーの完全盤仕様 〜**

## **第1章：用語定義（System Glossary）**

本章では、「Forest-gram」システム内で使用される、植物学的メタファーを伴う特有のシステム用語およびアーキテクチャ概念を厳密に定義する。

### **1.1 役割とエージェント分類（Roles & Agents）**

- **Forest-gram（フォレスト・グラム）：** 自律分散型知能の多層群れ（Multi-Agent System）と、GraphQLによる多次元血統マッピング、および現実の物理ファブリケーション制約を調和させるための生命型循環プラットフォーム。
- **庭師（Gardener / ユーザー）：** システムに計算資源（土壌）を提供し、smile（水分）を注ぎ、成果物の最終合意を行う人間（共同参加者）。
- **SUN Agent（太陽エージェント / PM）：** クラウドの超大型モデル（Gemini 2.5 Pro）を宿し、ユーザーの曖昧な要求をパース（光合成）して、依存関係（DAG）を解析したアトミックな「クエストチケット」に分解し、掲示板へ投下するオーケストレーター。
- **Tree Agent（樹木エージェント / 専門実動職）：** 自宅ローカルLLMを主たる脳とし、特定の技術タグ（例：\[Python/CAD-DXF\]）に特化した自律エージェント。カエデ（maple）やクルミ（walnut）などの樹木名を冠する。
- **Fungi Agent（菌類エージェント / 分解者）：** シイタケ（shiitake）などの名称を持ち、タスク完了後の仕掛品や失敗コードを構文解析（AST）し、役立つ部品だけを抽象化スニペット「腐植質（Humus）」として共有地へ還元するバックグラウンドプロセス。

### **1.2 生理・代謝作用（System Physiology）**

- **smile（☺ / スマイルエネルギー）：** システム内で循環する唯一の価値媒体（エネルギー）。API推論、生存代謝（24hごとの維持費）、自己訓練、交配の実行時に消費される。
- **トラストスコア（Trust Score / 生存信頼度）：** エージェントの稼働の真摯さ（一発クリア率）を示す 0 \\sim 100 の信用指標。30 未満になるとチケットPull権限が停止され、サンドボックスに強制隔離される。
- **木化（Lignification / 堅牢硬化）：** CI/CD検証とユーザーの主観評価をパスしたソースコードやアセットを、読み取り専用（chmod 444）に物理変更し、以後の改変やハルシネーションによる破壊から不変保護するプロセス。
- **剪定（Pruning）：** 推論が無限ループに陥る、または中間ファイルが急激に異常肥大化したエージェントスレッドを、OSレベルの SIGKILL で強制終了する自律保護。
- **落葉（Defoliation）：** タスクがアイドル状態に入った際、ローカルLLMのコンテキストメモリを完全解放し、ホストマシンのVRAM使用率を 0 GB 付近までアンロードする物理リソースクレンジング。
- **腐植質（Humus）：** 菌類エージェントが分解・純化した汎用コードスニペット。新芽（新規個体）の誕生や待機時間中の自己訓練（ワクチン摂取）にRAG参照される「知の土壌」。
- **形質置換（Character Displacement / ニッチ自動棲み分け）：** 同じタグを求めてロック競合を繰り返すエージェント同士が、重複指数（ピアニカの指数）の警告に基づいて、自身のプロンプトと専門サブタグを自律的に別領域へ細分化・シフトする調停作用。

## **第2章：データベース設計書（Database Design Specification）**

Forest-gramのステータス管理、家系図の多次元追跡、およびファイル位置のマッピングは、関係性一貫性（ACID）を担保するためにリレーショナルデータベース（SQLite / PostgreSQL）上に実装される。

### **2.1 物理E-R図（テキスト記述表現）**

`[users] 1 ───────── 0..* [tree_agents]`  
 `│ 1`  
 `├─────────── 1..* [episodic_logs] (10件制限)`  
 `├─────────── 0..* [traits] (バフ・デバフ)`  
 `│`  
 `├─────────── 0..* [agent_skills] (多対多)`  
 `│                  │`  
 `[skills] 1 ────────────────┘                  │`  
 `▼`  
 `[quests] 0..* ─────────────────────── 0..1 [tree_agents] (担当)`  
 `│`  
 `└──────── 0..1 [projects]`

`[genealogy] 0..* ─── 2 (parent_a, parent_b) [tree_agents]`  
 `└────── 1 (child) [tree_agents]`

### **2.2 テーブル一覧とスキーマ定義**

すべてのプライベート/パブリックデータは、以下の物理テーブルで管理される。

#### **① users（庭師マスターテーブル）**

ユーザー（オペレーター）の認証情報、Tailscale経由のスマホ識別子、および保有smileの総量を管理。

#### **② tree_agents（樹木エージェントマスタテーブル）**

各エージェントの基本ステータス、レベル、系統、現在のsmile残高を保持。

#### **③ quests（クエストチケットテーブル）**

SUN Agentによって切り出されたアトミックなタスク。状態（OPEN, IN_PROGRESS等）および成果物パス。

#### **④ skills（グローバルスキルマスターテーブル）**

.forestgram/skills/ にマッピングされた、共通のツール定義およびスキーマ。

#### **⑤ agent_skills（エージェント保有スキル中間テーブル）**

エージェントとスキルの紐付け。交配時にシャッフルされる遺伝子の物理実体。

#### **⑥ genealogy（多次元血統マッピングテーブル）**

親子関係、クロスオーバー比率、突然変異フラグなど、GraphQLで再帰クエリされるコアテーブル。

#### **⑦ traits（動的状態異常・バフテーブル）**

「光合成」「虫食い」など、エージェントの現在のアクティブバフ・デバフを時間制限付きで管理。

#### **⑧ episodic_logs（短期エピソード記憶テーブル / FIFO 10件制限）**

Tree Agentごとのデバッグ履歴。11件に達した瞬間に要約統合され、物理デリートされる。

## **第4章：インフラ定義書（Infrastructure & Deployment Specification）**

Forest-gramは、ローカルPCの圧倒的なGPU推論パワーと、Google Cloudの強固なクラウドバックボーンを Tailscale メッシュVPNで安全に跨ぐ、**ハイブリッドインフラ構成**を採用する。

### **4.1 ローカル環境仕様（自宅PCホスト・エージェントファーム）**

- **OS / カーネルレイヤー：**
  - **OS:** Ubuntu 24.04 LTS (物理サーバーとしてヘッドレス運用、または Windows 11 Pro \+ WSL2 Docker環境)
  - **GPUドライバ:** NVIDIA Driver 550+、CUDA Toolkit 12.4
- **LLM推論ホスティング（Ollama）：**
  - システムプロセス、またはDockerコンテナとして稼働。
  - **提供ポート:** 11434（TailnetインターフェースにのみBIND制限。パブリックインターネットからは物理隔離）
  - **稼働モデル:** gemma2:9b-instruct-q8_0, gemma2:2b-instruct-fp16 (先駆期用), llama3.1:8b-instruct-q8_0
- **ローカルリバースプロキシ（Caddy Server / Nginx）：**
  - **役割：** Tailscaleが自動生成するHTTPS証明書（TLS）を管理し、Webフロントエンド（Next.jsポート3000）およびGraphQL API（Hasura/FastAPIポート4000）をモバイルブラウザへ安全に公開。
  - **Caddyfile定義例（物理マッピング）：**  
    `forest-gram.tailnet-name.ts.net {`  
     `# Webアプリアバターキャンバスへのプロキシ`  
     `reverse_proxy / https://localhost:3000`

        `# GraphQL APIエンドポイントへのプロキシ`
        `reverse_proxy /graphql https://localhost:4000/graphql`

        `# SSL証明書は Tailscale デーモンから自動取得して自動更新`
        `tls {`
            `get_certificate tailscale`
        `}`

    `}`

### **4.2 クラウド環境仕様（Google Cloud \- コアバックボーン）**

自宅PCが予期せぬ停電や、木工CNC加工中のリソース逼迫でオフラインになっても、プロジェクトの仕様分解（SUN Agent）や、蓄積された家系図データ、アセット画像を消失させないため、Google Cloudへ主要システムの一部をミラー・冗長化デプロイする。

1. **Vertex AI / Gemini API Integration：**

- **使用モデル:** gemini-flash-latest (SUN Agent、交配ルールマージ用)、gemini-flash-lite-latest (画像ピクセレーションのソース画像生成：gemini-3.1-flash-image経由)
- **接続経路:** ローカルホストおよびクラウド環境から、サービスアカウントキー認証、またはWorkload Identity（推奨）を用いて Vertex AI SDK へセキュアに疎通。

1. **Cloud Run（フロントエンド＆API中継コンテナ）：**

- **役割：** いつでも、どこからでも接続可能なグローバルWebコンソール（Next.jsコンテナ）のホスティング。
- **構成：**
  - 完全サーバーレス、最小インスタンス数 0、アクセス時に動的スケール。
  - **Tailscale Sidecar Container Configuration:** Cloud Runコンテナ内に Tailscale の軽量デーモンをサイドカーとして同乗させ、GCP上のVPCネットワークと自宅PCのローカルホストネットワークを完全な同一 Tailnet 内に仮想接着。これにより、パブリックなインターネット上にポートを1つも晒すことなく、Cloud Run から自宅のローカル Ollama API（100.x.y.z:11434）へ直接セキュアに推論要求をルーティング（中継）する。

1. **Cloud SQL for PostgreSQL（多次元データベースミラー）：**

- **役割：** ローカルのSQLiteデータの永続バックアップミラー。GraphQLHasuraエンジンと直結。
- **構成：**
  - 最小構成（db-f1-micro、または共有CPUコア）。コストを抑えるため、開発中は非冗長構成。
  - 自宅PC側のGraphQLエンジンからの双方向レプリケーション同期をSSL暗号化接続で実行。

1. **Cloud Storage（アセットバケット）：**

- **役割：** エージェントたちの高解像度オリジナル画像（生画像）およびピクセレーション後のドットアバター、完成した物理設計DXF/G-codeデータの永続アーカイブ（コールドストレージ）。
- **構成：**
  - バケット名: gs://forestgram-assets-${appId}
  - 各ファイルのメタデータ（オブジェクトパス）は、GraphQL上の avatarUrl および deliverable_path と完全にマッピング同期。

### **5.2 データ遷移・状態遷移プロトコル（シーケンス）**

1. **ユーザー要求（受容）：** スマートフォンから https://forest-gram.ts.net（Tailscale MagicDNS）へアクセス。HTTPSで暗号化されたNext.js UIが立ち上がる。
2. **タスク分解（同化）：** ユーザーが曖昧な要件をスマホから投下。自宅PCのBackendは、Google Cloud上の Vertex AI gemini-flash-latest を叩き、大局的な依存関係（DAG）を解析させた上で、ローカルの SQLite データベース of quests テーブルへチケットをINSERT。
3. **自律スナッチ（Pull）：** 自宅PCの Ollama がリソースチェック（土壌と水分の監視）。メモリに余裕がある場合、Tree Agent（例：maple）が自身の agent.md に書かれたタグと合致するチケットを SQLite 上で楽観的ロック（CAS更新、二重取得を物理防止）をかけ、状態を IN_PROGRESS に変えてタスクをロック。
4. **ローカル推論実行：** maple は自宅PCの GPU（RTX）を使用し、Ollama経由の gemma2:9b で高速にコードおよびG-code、DXFを生成。成果物を projects/{id}/temporary/ に出力。
5. **テスト ＆ 木化（硬化）：** 自動CI/CDスクリプトがコンテナ上で実行。パスした場合、スマホUIに完了通知。ユーザーがスマホを親指でタップして「👍（★5）」を送信すると、成果物ファイルは projects/{id}/deliverables/ へコピーされ、OSレベルで chmod 444（木化）を施されて Cloud Storage へも冗長バックアップコミット。
6. **5Sクレンジングと分解：** タスク承認のトランザクション完了と同時に、菌類エージェント（shiitake）が temporary/ 内を分解（有用ロジックを RAG 共有地へコミット）した後、OSコマンド rm \-rf によって一時フォルダの中身を空にクレンジング（完全削除）。エントロピーをリセットして次の生存サイクル（代謝）へ移行。

本「大統一アーキテクチャ・インフラ・データベース設計書」で定義されたインフラ境界、GraphQLに適合したDBテーブル構造、およびTailscaleハイブリッドトポロジーは、Forest-gramにおけるすべての論理循環処理が、物理的なデバイス、メモリ、サーバー、および人間の指先と寸分の狂いもなくリアルタイム接地（Grounding in Reality）することを約束する。
