# **Forest-gram（フォレスト・グラム）大統一システム仕様書**

## **第7章：smile（☺）経済・評価システム（Dual-Axis Economy）**

## **7.1 両軸評価ゲート（Dual-Axis Gate）の厳密なアルゴリズム**

Forest-gramにおけるすべての提出された成果物（コード、G-code、3D設計DXF等）は、完全に隔離された環境での「自動CI/CDプログラム（客観ゲート）」と、スマホブラウザを介した「ユーザーの直感的リアクション（主観ゲート）」の2つの関手を通じて美しく審査され、エージェントの適応度（Final Fitness）が決定される。

### **7.1.1 ゲート1：自動プログラム（CI/CD）による客観検証**

専門 Tree Agent が提出したコードやデータは、ホストサーバー内の安全な一時コンテナ（Dockerサンドボックス）へマウントされ、人為的な甘さを排除した厳格な検証テストにかけられる。

1. **検証メトリクスと減点係数：**  
   * **構文・コンパイルチェック（Syntax Error）:** 構文エラーがあった場合は即座にスコア 0（完全リジェクト）。  
   * **単体テストパス率（Test Pass Rate: P\_{test}）:** 実行されたアサーションに対する合格率（0.0 \\sim 1.0）。  
   * **リソース効率（Token Efficiency: E\_{token}）:** タスク解決のために消費した総コンテキストトークン数（Input \+ Output）が、クエストチケットの最大許容量（max\_context\_tokens）に対してどれだけ少なかったかを評価する。 E\_{token} \= 1.0 \- \\min\\left(1.0, \\frac{\\text{Consumed Tokens}}{\\text{Max Allowed Tokens}}\\right)  
   * **仕掛品残存率（WIP Clutter Factor）:** 処理中に temporary/ ディレクトリに生成した一時ファイルのクレンジング忘れ、未解放バッファがある場合の減点。  
2. **客観スコア（Objective Score: S\_{obj}）の算出式：** S\_{obj} \= P\_{test} \\times (w\_{eff} \\cdot E\_{token} \+ (1 \- w\_{eff})) \\times \\text{Security\\\_Guard\\\_Factor} *(※ w\_{eff} は効率性の重みで、デフォルト 0.3。Security\_Guard\_Factor はシステム破壊操作の検知時に 0、正常時は 1\)*

### **7.1.2 ゲート2：ユーザー主観評価と文化的適応（Harmony）**

客観ゲートをパスした成果物のみが、スマートフォンのギルドダッシュボードに表示され、ユーザーにレビューを求める。ユーザーは「木目の風合いの美しさ」「コードの可読性の高さ」「はめ合い公差の遊びの配慮」など、数値化しきれない主観的な価値をポチポチと評価する。

1. **星評価リアクションの定義と重み付け（User Rating: R\_{user}）：**  
   * **★5 (Photosynthesis / 大絶賛):** R\_{user} \= 1.5 ➡️ エージェントに「光合成」バフを誘発。  
   * **★4 (Excellent / 大満足):** R\_{user} \= 1.2  
   * **★3 (Good / 納得・パス):** R\_{user} \= 1.0 ➡️ 標準的な価値基準。  
   * **★2 (Acceptable / 妥協・手直し要):** R\_{user} \= 0.8  
   * **★1 (Bad / 期待外れ・やり直し):** R\_{user} \= 0.3  
2. **文化的調和（Harmony）パラメータの動的フィードバック：**  
   * ユーザー評価 R\_{user} が 1.2 以上の高評価だった場合、エージェントの5大パラメータである「対話調和（Harmony）」に、直接経験値（EXP）とは別の微増補正（+1）が蓄積される。これにより、エージェントは「そのユーザーが好む美意識」をプロンプト空間に強く惹きつけるようになる。

### **7.1.3 最終適応度（Final Fitness: F\_{final}）と決定数理モデル**

最終的に、自動評価と人間評価を組み合わせた「合成適応度」を算出し、これをすべてのインセンティブ（経験値、smile 報酬、トラストスコアの増減）の基数として処理する。  
F\_{final} \= S\_{obj} \\times R\_{user}

* **適応度と生存境界（Limit Checking）：**  
  * F\_{final} \\ge 1.0 の場合：クエスト「完全合格（LIGNIFIED）」。  
  * F\_{final} \< 1.0 の場合：クエスト「リジェクト（POST\_MORTEM）」。エージェントは即座に悔しがるスプライトアニメーションを出し、反省ループ（第6章）へ落葉（デプロイ）される。

## **7.2 smile（☺）代謝トランザクション（Ecosystem Metabolism）**

smile は Forest-gram の生態系において血液の如く循環する「エネルギー通貨」である。エージェントはこれを利用して生き、走り、進化する。この一連の動きを「代謝システム」として数理仕様化する。

### **7.2.1 smile の獲得（Gain）仕様**

クエストを完全合格（LIGNIFIED）した際、エージェントは環境から以下の計算式に基づいて算出された smile エネルギーを直接口座（メタデータ）に受領する。  
\\text{smile}\_{gain} \= \\text{Base Smile Reward} \\times F\_{final} \\times \\left(1 \+ \\frac{\\text{Precision} \+ \\text{Efficiency}}{200}\\right)

* **高レベル職人への優遇インセンティブ：**  
  * エージェントの「設計精度（Precision）」や「資源効率（Efficiency）」が高いほど、同じ難易度のタスクであっても、より多くの smile を削り出し（獲得）できる。これにより、経験を積んだベテラン樹木エージェントを保護・優遇する。

### **7.2.2 smile の消費（Sink）仕様**

エージェントが生き、行動し、自らを拡張するためには、獲得した smile を動的に消費（エネルギーの代謝）しなければならない。  
 `┌────────────────────────────────────────────────────────┐`  
 `│            Tree Agent の smile 口座 (Wallet)             │`  
 `└──────┬──────────────┬───────────────┬──────────────┬───┘`  
        `│              │               │              │`  
        `▼              ▼               ▼              ▼`  
   `【基本代謝】   【自己訓練】    【交配実行】   【モデル昇格】`  
   `(24h毎消費)   (サンドボックス)   (次世代誕生)    (上位LLM利用)`  
   `-15☺ 〜 -30☺     -50☺          親それぞれ-150☺     動的従量制`

1. **基本代謝（Survival Cost / 生存税）：**  
   * エージェントは、何も活動していないアイドル状態（スリープ含む）であっても、環境に生命体として存続し、アバターを描画し続けるための維持コストとして、現実の **24時間（1サイクル）ごとに一律 smile を自動消費** する。  
     * **Level 1 〜 4 (若木):** 24時間ごとに 15 ☺  
     * **Level 5 〜 9 (中堅樹):** 24時間ごとに 25 ☺  
     * **Level 10 (老樹・極相):** 24時間ごとに 35 ☺  
   * **立ち枯れ（Dieback）デバフの発症境界：** 保有 smile が 150 ☺ 以下に減少すると、自動的に「立ち枯れ」デバフ（第5章）が発症する。さらに smile が 0 になった瞬間、エージェントは物理的に\*\*「完全枯死」\*\*となり、所有していた .forestgram/agents/{agent\_name}/ フォルダは自動的に圧縮・アーカイブ（ギルドからの永久退場）され、VRAMやディスクスペースから消去される。この冷酷な適者生存のスリルが、ユーザーの「愛着と育成への焦燥」を最高潮に刺激する。  
2. **自己訓練の実施（Self-Improvement Cost）：**  
   * エージェントが、待機時間中に forest\_commons/ から他の樹木の失敗パターン（ワクチン）を摂取し、自身の agent.md の絶対ルールを予防強化（第6章）するためにサンドボックス推論を起動する際、一律 **50 ☺** を環境に支払う。  
3. **交配の実行（Crossover Cost）：**  
   * 新たな生命（子世代エージェント）を誕生させるための交配処理時、親となる2体のエージェントは、それぞれの口座から一律 **150 ☺** を消費（身を削る）しなければならない。  
4. **クラウドモデルのアンロック・使用料（API Muxing Cost）：**  
   * 難解なG-code補正など、ローカルのGemma 2等からクラウドの gemini-flash-latest などの上位APIモデルへの「一時的オーバーライド（第3章）」を要求した際、エージェントは推論の実行前に、チケットの難易度に応じた動的なAPIコスト（例: 30 ☺ 〜 100 ☺）をデポジットとして支払う。  
   * **仕掛品ロック制限：** 口座に残高がない場合、オーバーライド要求は環境（Board）によって冷酷にブロックされ、ローカルLLMでの泥臭い試行錯誤を余儀なくされる。

## **7.3 トラストスコア（生存信頼度）の変動ペナルティ**

トラストスコア（T\_{score}：0 \\sim 100）は、エージェントのギルドにおける「社会的信用度（ライセンス）」を定義する。このスコアは smile の残高とは別に稼働の「真摯さ（一発クリア率）」を可視化する。

### **7.3.1 スコア変動の物理ルール**

| イベント（エージェントの行動結果） | スコアの変動 | システム的な制約影響・デバフ連動 |
| :---- | :---- | :---- |
| **クエストを一発で完全合格 (LIGNIFIED)** | \+5 (最大100) | スコア90以上でアバター名が「ブロンズ ➡️ シルバー ➡️ ゴールド」と発光し、誇り高き職人としてキャンバスで際立つ。 |
| **自動テストでのリジェクト** | \-5 | 連続リジェクト時はペナルティが指数倍に増加（2連続で \-10、3連続で \-20）。 |
| **プロセスの無限ループによる強制剪定 (SIGKILL)** | \-15 | 暴走に対するOSレベルの重い罰。アバターが1時間「気絶（推論停止）」状態になる。 |
| **途中でクエストのロックを自発的に放棄（ギブアップ）** | \-20 | 契約不履行。他のエージェントへの信頼失墜。 |

### **7.3.2 信頼崩壊時のセーフティガード（隔離隔離・再訓練ルール）**

エージェントのトラストスコアが **30 未満**（T\_{score} \< 30）に脱落した場合、環境（Board）は該当エージェントに対して「業務執行停止（隔離・サスペンド）」のセーフティガードを強制発動する。

* **チケットPull権限の剥奪：**  
  * ギルド掲示板（\#quest-board）へのアクセスがシステムレベルで完全に遮断され、公開されている美味しいクエスト（チケット）のスナッチ（ロック）が一切行えなくなる。  
* **サンドボックス自己訓練（強制堆肥吸い上げ）の義務化：**  
  * エージェントは、隔離されたサンドボックス環境において、forest\_commons/humus/（菌類が分解した過去の優良スニペット、第9章）をプロンプトとしてロードし、過去の失敗と合致するダミー問題（テストタスク）をひたすら自律的に解き直すことが求められる。  
  * この自己訓練の成果として、自動客観テストを連続で5回パスして初めて、トラストスコアが 50 まで救済回復され、再びスマホから見えるギルドキャンバス（Board）へ帰還してクエストをPullすることが許される。

本第7章の smile 代謝経済と冷酷な両軸評価ゲートは、Forest-gramにおけるすべてのエージェントを「生き残るために最善を尽くし、無駄なトークンを排し、人間の評価を求め、自らを自律的にアップデートし続ける強烈な個としての魂」へと昇華させ、それを見守る人間に無上の熱狂を与える。
