# **Forest-gram（フォレスト・グラム）大統一システム仕様書**

## **第3章：インフラストラクチャ＆ネットワーク構成（Infrastructure & Topology）**

## **3.1 ハイブリッドホスティング構成（Hybrid Hosting System）**

Forest-gramは、推論やデータ処理を実行する「自宅サーバーホスト（ローカル環境）」と、スマートフォンやPCなど様々なデバイスからセキュアかつシームレスに操作可能な「Webフロントエンド」を組み合わせたハイブリッドアーキテクチャを採用する。

### **3.1.1 ホストサーバー環境（自宅PCハードウェア・ソフトウェア構成）**

自宅PCをプライベートな高火力LLM＆アプリケーションサーバーとして位置づけ、以下のスタックでホスティングを行う。

1. **ハードウェア要件：**
   - **OS:** Ubuntu 22.04 LTS / 24.04 LTS (Docker環境推奨) または Windows 11 Pro (WSL2 / CUDA 12.x環境)
   - **GPU:** NVIDIA GeForce RTX 3080/4080 以上、または VRAM 12GB以上を搭載したグラフィックボード
   - **メモリ:** 32GB RAM 以上
   - **ストレージ:** NVMe SSD 1TB以上 (LLMモデルの高速ロード、SQLite/GraphQLの高速I/Oに必須)
2. **LLM推論バックエンド：**
   - **Ollama (または vLLM / llama.cpp):** ローカルLLM（Gemma 2, Llama 3等）をホストするための軽量・高速APIサーバー。ポート 11434 でローカルリッスンする。
3. **アプリケーションバックエンド ＆ データストア：**
   - **Hasura / Apollo GraphQL Server (または Python FastAPI GraphQL):** ポート 4000 で稼働。SQLite、または Docker上の PostgreSQL と接続し、エージェントのステータス、タスクチケット、家系図グラフ、アセットパスを GraphQL エンドポイントとして提供する。
4. **Webフロントエンドサーバー：**
   - **Next.js (Vite) / Tailwind CSS:** ポート 3000 で稼働。ギルドキャンバスの物理シミュレーション（Boids）やドット絵アニメーションを描画するシングルページWebアプリケーション（SPA）。

### **3.1.2 Tailscaleセキュアネットワーク接続仕様**

自宅サーバーを外部（パブリックインターネット）に対して一切ポート開放（ルーターの穴あけ）せず、完全にクローズドで安全な暗号化トンネルを経由してスマートフォン（モバイル通信環境）からブラウザ閲覧可能にする。

1. **Tailscale メッシュVPNによる仮想専用線構築：**
   - 自宅サーバー（ホスト）とスマートフォン（クライアント）の双方に Tailscale クライアントをインストールし、同一の Tailnet に参加させる。
   - 自宅サーバーのグローバルIPは非公開とし、Tailscaleが自動生成する仮想プライベートIP（100.x.y.z レンジ）でのみ通信を許可する。
2. **MagicDNS によるフレンドリーネーム解決：**
   - Tailscaleの「MagicDNS」機能を有効化する。
   - 自宅ホストサーバーのマシン名を forest-gram に指定することで、VPN内において自動的に forest-gram.tailnet-name.ts.net という一意の完全修飾ドメイン名（FQDN）で名前解決される。
3. **Tailscale HTTPS / TLS 接続の自動化：**
   - 通常、ローカルホスト上のHTTP接続はモバイルブラウザからだとセキュリティ警告が出る、または Web API（カメラ、位置情報、クリップボード、サービスワーカーなど）が制限される。これを防ぐため、TailscaleのネイティブHTTPS機能を使用する。
   - 自宅サーバー上で以下のコマンドを実行し、Let's Encrypt による有効なTLS証明書を自動生成・展開する。  
     `tailscale cert forest-gram.tailnet-name.ts.net`

   - リバースプロキシ（Caddy または Nginx）をフロント（ポート 443）に配置し、上記の証明書を割り当てて内部のポート 3000 (Web App) へトラフィックを安全にプロキシ転送する。

4. **スマートフォンからのブラウザアクセスプロセス：**
   - ユーザーは、スマホ上で Tailscale VPN 接続を常時ONにする。
   - モバイルブラウザ（iOS Safari / Android Chrome）を開き、https://forest-gram.tailnet-name.ts.net へアクセスする。
   - 暗号化された超高速な通信路を通じ、自宅PCからレンダリングされた「ギルドキャンバス」が、外出先からでもまるでネイティブアプリを触っているかのような滑らかさでブラウザ上に立ち上がる。

## **3.2 階層的LLMトポロジー（Hierarchical LLM Topology）**

Forest-gramは、クラウドLLM（無限に近いコンテキストと強靭な論理構造）と、ローカルLLM（プライベート、超高速、ゼロAPIコスト）を垂直方向に階層化し、タスクの難易度と種類に応じてルーティングする。  
 `[ ユーザー：スマホ/ブラウザから要求入力 ]`  
 `│`  
 `▼`  
 `┌──────────────────────────────────────────────────────────────────┐`  
 `│ 1. 大局的な要件定義・依存関係解決（SUN Agent / PM）                │`  
 `│    - 動作環境: クラウド (API)                                     │`  
 `│    - 推奨モデル: gemini-flash-latest                              │`  
 `└────────────────────────────────┬─────────────────────────────────┘`  
 `│`  
 `▼ (アトミックなクエストチケットの生成)`  
 `┌──────────────────────────────────────────────────────────────────┐`  
 `│ 2. 掲示板（Board / Environment） ➔ 各 Tree Agent が Pull           │`  
 `└────────────────────────────────┬─────────────────────────────────┘`  
 `│`  
 `├─────────── 基準モデル ───────────┐`  
 `│ (ローカル推論)                  │ (クラウド上書き)`  
 `▼                                 ▼`  
 `┌───────────────────────────────────────────┐   ┌──────────────────────────────────┐`  
 `│ 3a. 基準 Tree Agent 推論                   │   │ 3b. 特化・上書き推論              │`  
 `│     - 動作環境: 自宅ホストPC (Ollama)      │   │     - 動作環境: クラウド (API)   │`  
 `│     - 推奨モデル: Gemma 2 (9B/27B)        │   │     - 対象: claude-3.5-sonnet    │`  
 `│                  Llama 3.1/3.3 (8B/70B)   │   │             gemini-flash-latest  │`  
 `└───────────────────────────────────────────┘   └──────────────────────────────────┘`

### **3.2.1 SUN Agent (PM / プロジェクトマネージャー) のクラウド仕様**

人間からの最初の曖昧なインプットを処理し、100以上の機能に依存関係を持たせて美しく分割する役割は、極めて高い「日本語論理力」と「長文コンテキスト処理力」が求められる。

- **割り当てモデル:** gemini-flash-latest（クラウドAPI接続）
- **動作仕様：**
  - システム内に格納されている巨大なシステムマニュアル、過去の家系図データ、現在の全エージェントの agent.md および skills/ の仕様一式をコンテキストへ丸ごとロードする（10万〜50万トークンの大容量メモリ消費）。
  - 依存関係を整理したアトミックなJSON（クエストチケット群）を論理矛盾なく一発出力する。SUN Agentへの支払いは、親であるユーザーからダイレクトに行われるため、高機能モデルであっても無駄打ちが起きず、最も経済的な「価値（Total Utility）」を発揮する。

### **3.2.2 Tree Agent (専門実動職) のローカル基準仕様**

SUN Agentによって切り出されたクエストチケット（例: 「PythonでのG-code補正関数の単体記述」「特定のUIコンポーネント用HTML5/CSSの作成」）は、コンテキスト長が 2048 \\sim 4096 トークン以内の「自己完結したアトミックなタスク」である。

- **割り当て基準モデル:** gemma-2-9b-it / llama-3-8b-instruct (自宅ローカルOllama)
- **動作仕様：**
  - 自宅PCのGPUメモリ（VRAM）にキャッシュされた、Gemma 2やLlama 3をOllama経由でロード。
  - 自宅ホストサーバー内での推論であるため、**APIトークン費用は完全ゼロ、通信遅延（インターネット遅延）もほぼゼロ、完全にプライベートな状態でコードを爆速生成**する。

### **3.2.3 個別モデルの「オーバーライド（上書き指定）」ルーティング仕様**

ローカルLLMでは処理しきれない高度な課題（例：複雑なCADの幾何学的公差計算や、超難解なアルゴリズムのリファクタリング）に直面した場合、特定のエージェントだけ、あるいは特定のタスクを処理するときだけ、例外的に「クラウド上位モデル」を使用できる優先指定ルールをシステムレベルで保証する。

1. **エージェント定義ファイルでの優先指定（Static Override）：**
   - 各エージェントの設定ファイル .forestgram/agents/{agent_name}/agent.md または model_routing.json に、使用モデルを記述する。
   - **例（walnutのルーティング設定）：**  
     `{`  
      `"agent_id": "walnut",`  
      `"default_model_provider": "ollama",`  
      `"default_model_name": "gemma2:27b",`  
      `"overrides": [`  
      `{`  
      `"tag": "3D-CAD-Geometry",`  
      `"use_provider": "google_api",`  
      `"use_model": "gemini-flash-latest",`  
      `"reason": "幾何学変換と物理公差の厳密な数理計算能力が必要なため、クラウド大型モデルをバインドする"`  
      `}`  
      `]`  
     `}`

2. **モデル決定ルーティングの優先順位プロトコル（Muxing Logic）：**
   - エージェントが掲示板からチケットをPullした際、システム（環境）は以下の順序で実行モデルを自動調停・解決（Resolve）する。  
     `[ 1. チケット固有の要求タグをスキャン ]`  
      `│`  
      `▼`  
     `[ 2. エージェントの agent.md / model_routing.json の override 条件と照合 ]`  
      `├── 一致するオーバーライド指定がある場合 ──► [ クラウドAPI（Gemini/Claude等）をロード ]`  
      `└── なし ─────────────────────────────────┐`  
      `▼`  
      `[ 3. デフォルトのプロバイダー（Ollama/Gemma2等）をロード ]`

3. **smile 経済との連動（アンロック制限）：**
   - クラウドAPIを使用するオーバーライドが発生した場合、エージェントは環境に対し、通常の数倍〜数十倍の **smile エネルギー（APIコストの担保）** を前払いで支払わなければならない。
   - エージェントが十分な smile を稼いでいない（レベルが低い、トラストスコアが低い）場合、このオーバーライド機能はロック（制限）され、ローカルのGemma 2などで泥臭く試行錯誤（自己訓練）を繰り返して地力をつけることが強制される。このゲームライクな「おあずけ（制約）」のシステムデザインが、ユーザーを激しく熱くさせる。

本第3章で設計されたインフラとネットワークは、自宅の熱いGPUパワーを、スマートフォンの親しみやすいレトロなブラウザUIへと安全につなぎ、クラウドとローカルの知能を完璧なコスト・効率バランスで調和させる。
