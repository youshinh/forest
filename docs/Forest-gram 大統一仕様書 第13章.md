# **Forest-gram（フォレスト・グラム）大統一システム仕様書**

## **第13章：開発フェーズと曳光弾ロードマップ（Tracer Bullet Milestone）**

## **13.1 曳光弾（Tracer Bullet）としての最小垂直スライス設計**

どれほど精緻な生態系も、最初の一粒の種から、根を張り、双葉を開くことでしか始まらない。 Forest-gramの実装における最優先課題は、複雑なマルチエージェントを一度に作り込もうとして「全結合のカオス」に陥るのを防ぐことである。第一原理に基づき、1つのアトミックなタスクが、要件の投入から最終的な「木化（コード凍結）」および「分解（クレンジング）」まで一気通貫で流れる\*\*「曳光弾（Tracer Bullet / 最小垂直スライス）」\*\*を Step 1 として定義する。

### **13.1.1 Step 1: 最小構成チーム（The Seed Team）の定義**

最初にデプロイし、環境との接地を確認するエージェントおよびインフラの最小セットは以下の通り。

1. **環境（Board）：**  
   * SQLiteデータベース（1テーブル：tickets）のみ。  
   * インターフェースは、ローカルPCのターミナル（CLI）および1つのローカルディレクトリ。  
2. **SUN Agent (PM / クラウドLLM / 1体)：**  
   * gemini-flash-latest APIを使用。ユーザーからの単純な要件を受け取り、依存関係のない2つのクエストチケット（JSON）をSQLiteにINSERTする機能のみ。  
3. **Pioneer Tree Agent \- willow (先駆樹 / ローカルLLM / 1体)：**  
   * Ollama上で稼働する超軽量モデル（例: gemma:2b または llama3:8b）。  
   * willow の .forestgram/agents/willow/agent.md には、\[Python/Calculator\] の単一タグのみを記述。  
4. **Fungi Agent \- shiitake (分解者 / ローカルLLM / 1体)：**  
   * gemma:2b で稼働。不適合エラーログから「役に立つコードブロック」を抽出し、forest\_commons/humus/ へマークダウンで保存する機能のみ。

### **13.1.2 曳光弾実証テストシナリオ（一撃必殺のループ検証）**

以下のシナリオを実行し、システムがエラーを出さずに自己組織化して1ループを完遂するかを実証する。

#### **【入力（要件投下）】：**

ユーザーが \#reception 代わりのテキストファイル raw\_requirements.txt に、以下の一文を書き込む。  
「メープル材の100mm幅の板が、湿度11%から15%になったときの膨張寸法を計算するPython関数を書いて。クリアランス逃げは不要」

#### **【プロセスフロー】：**

 `1. [SUN Agent] が起動`  
      ``│ ➔ 要求をパースし、単一チケット `FG-001` (タグ: [Python/Calculator]) を SQLite に公開。``  
      `▼`  
 `2. [willow] が SQLite をポーリング`  
      `│ ➔ 自身のタグと合致したため、チケットを楽観的排他ロック（CASロック）。`  
      ``│ ➔ ローカルの Ollama (gemma:2b) で推論を実行し、`projects/PRJ-01/temporary/calc.py` を出力。``  
      `▼`  
 `3. [環境自動テスト] が起動`  
      ``│ ➔ `python3 projects/PRJ-01/temporary/calc.py` をサンドボックス実行。``  
      `│ ➔ (合格ケース): 15%MCでの膨張（100 * 0.0035 * 4 = 1.4mm）を正しく計算。`  
      ``│                  成果物を `deliverables/` へコピー。``  
      `▼`  
 `4. [木化 (Lignification)] の実行`  
      ``│ ➔ `deliverables/calc.py` のパーミッションを `chmod 444`（読み取り専用）に変更。``  
      `▼`  
 `5. [5Sクレンジングと分解]`  
      ``│ ➔ `shiitake` が起動し、`temporary/` の中身をスキャン。``  
      ``│ ➔ 正常稼働関数を `forest_commons/humus/` に自動アーカイブ。``  
      ``│ ➔ `projects/PRJ-01/temporary/` ディレクトリを完全物理削除（rm -rf）。``

この一連の動きが、人間の一切のデバッグ介入（Push）なしで、自律PullとSQLiteの状態遷移のみで100%回りきった段階で、Forest-gramの「生命としての骨格（Tracer Bullet）」は実証されたとみなす。

## **13.2 段階的進化ロードマップ（Development Milestones）**

曳光弾の実証完了後、以下の5つのミリタリーマイルストーンに従って、システムに肉体、生理機能、経済、血脈、そして極上のビジュアルを段階的に組み上げていく。  
 `[ Step 1: 曳光弾実証 ] ──► [ Phase 1: 地下インフラ ] ──► [ Phase 2: 生理機能(VRAM解放) ]`  
                                                                      `│`  
                                                                      `▼`  
 `[ Phase 5: ビジュアル描画 ] ◄── [ Phase 4: 経済と血脈 ] ◄── [ Phase 3: 脳と筋肉(MCP) ]`

### **13.2.1 Phase 1: 地下インフラの開拓（ネットワーク ＆ DB結合）**

* **マイルストーン目標：** 自宅サーバーの物理的・論理的インフラを整え、スマホからCLIメッセージを叩ける環境を作る。  
* **実施事項：**  
  * 自宅PCへの Docker, Ollama, Hasura GraphQL Engine, Tailscale の導入。  
  * Tailscale MagicDNS を有効化し、https://forest-gram.tailnet-name.ts.net でGraphQLエンドポイントへのセキュア接続テスト。  
  * エージェントの初期定義 .forestgram/agents/ の手動Gitリポジトリ化。

### **13.2.2 Phase 2: 剪定・落葉・木化生理機能の実装**

* **マイルストーン目標：** 計算資源の浪費による自宅PCのクラッシュを完全に防ぐセーフティシステムを組む。  
* **実施事項：**  
  * プロセス監視デーモンの実装：実行時間が制限値（60秒）を超えたエージェント推論プロセス（PID）に対し、OSレベルで SIGKILL を送り「剪定」するプロトコル。  
  * 落葉（VRAMアンロード）機能の構築：タスクが REVIEW または OPEN に戻った際、Ollamaの /api/generate またはモデルキャッシュを解放し、ホストGPUのVRAM使用率を 0 GB 近辺まで引き下げる。  
  * 木化機能：CI/CDテストを3回連続で通した deliverables/ 内のコードに対して、自動で chmod 444 を適用するロックエンジンの開発。

### **13.2.3 Phase 3: 脳と筋肉の結合（MCP・skills/一元管理）**

* **マイルストーン目標：** エージェントプロンプトからPythonやシステム制御コードを100%パージし、定型に準拠したセキュアなツール実行環境を作る。  
* **実施事項：**  
  * 共通 .forestgram/skills/ ディレクトリの作成。schema.json と execute.py を持たせた gcode\_optimize や dxf\_parse の開発。  
  * forest-gram-mcp-server の実装：エージェントが発したツールコール（JSON-RPC 2.0）を検証し、許可された projects/ 領域内でのみ安全にサブプロセス実行するゲートウェイの構築。

### **13.2.4 Phase 4: 経済（smile）と血脈（家系図・突然変異）の連動**

* **マイルストーン目標：** 生態系の「お金（エネルギー）」と「交配」による自己組織化進化を実装する。  
* **実施事項：**  
  * smile トランザクションの実装：クエストクリアによる口座への smile 加算、24時間ごとの「基本維持コスト（生存税）」の自動引き落とし、残高ゼロ時の「枯死アーカイブ（フォルダの自動ZIP退場）」機能。  
  * 交配エンジン開発：親Aと親Bの5大パラメータから blend ratio \\alpha と突然変異（Normalノイズ）を乗せて子パラメータを算出。親の agent.md から Absolute Rules をLLMで矛盾なく自動マージ（マージプロンプト）。  
  * ピアニカの重複指数 O\_{jk} に基づく「自動形質置換（タグ棲み分け）」の自律バックグラウンド処理。  
  * GraphQLによる多次元親子関係（Ancestors / Descendants）のデータベース結線・クエリ機能。

### **13.2.5 Phase 5: ビジュアルキャンバスの生命化（UX）**

* **マイルストーン目標：** スマートフォンのブラウザにドット絵の「原生林」を描画し、お世話コマンドで親指一つで生命と触れ合う。  
* **実施事項：**  
  * HTML5 Canvas または WebGL を使用した、チケットへエージェントが「群がる」Boids物理スワームの動的フロントエンド描画。  
  * gemini-flash-latest の出力画像を、クライアント側（HTML5 Canvas ImageData 処理）で白背景透過 ➔ 最頻値ダウンサンプリング ➔ ソベル境界茶アウトライン ➔ パレット制限する「ピクセレーション・パイプライン」のWebGLシェーダー化（高速化）。  
  * 立ち枯れ（茶パレット）、光合成（金色パーティクル）、虫食い（モゾモゾ這い回る虫ドットスプライト）のレイヤー合成描画。  
  * レベルアップ時の画面暗転「ファンファーレ・紙吹雪スプライト」の実装。

## **13.3 テスト駆動開発（TDD）による自己組織化検証シナリオ**

システムの完全なる自律（エゴを排除した現実接地）を保証するため、以下の2つの極限検証テスト（統合ブラックボックステスト）を自動テストスイートに組み込む。

### **13.3.1 テストシナリオA：ハルシネーション（エゴ）の物理的粉砕テスト**

* **検証目的：** エージェントが「私は完璧なコードを書いた。このエラーは環境（テスト）側が間違っている」とハルシネーション（自己陶酔）を起こした際、システムがそれを即座にリジェクトし、強制反省（Resilience）させ、現実の制約に屈服させるかどうか。  
* **テスト方法：**  
  1. 意図的に「絶対にコンパイルが通らない構文エラーを含んだタスクチケット」を Board に投下。  
  2. エージェントが「完成した」としてコードを提出（REVIEW）。  
  3. 客観ゲート（コンパイラ）がエラーを吐いてリジェクト。  
  4. **合格判定：**  
     * エージェントがコンパイラを罵倒する（ハルシネーションに固執する）ことなく、エラーログを真摯に受け止め、自身の episodic\_log.json に「私の不注意により構文エラーが発生した」と記録。  
     * かつ、2回目の試行で構文規約（Absolute Rules）に安全ガードを自動追記してコンパイルをクリアすること。

### **13.3.2 テストシナリオB：極限干ばつ（リソース制限）への自己防衛テスト**

* **検証目的：** ホストマシンのリソース（メモリ/VRAM）が逼迫した際、エージェントたちが「枯死」を避けるためにモデルを自律的にダウングレードさせ、計算負荷を切り詰めて生き残るか。  
* **テスト方法：**  
  1. テストスクリプトによって、ホストPCの空きメモリ（RAM）を強制的に10%以下に圧迫（干ばつの擬似再現）。  
  2. エージェントが新たなクエストチケットをPull。  
  3. **合格判定：**  
     * エージェントの running\_state.json に「Drought（干ばつデバフ）」が自動検知され、デフォルトの gemma-2-27b-it（中型）から、軽量ローカルSLM gemma-2-2b-it へのルーティング自動切り替え（モデルオーバーライドの抑制）が発生すること。  
     * APIコスト（smile）を極限まで低減させた状態で、タスクを軽量にクリアすること。

本第13章のロードマップ、および曳光弾仕様の定義により、Forest-gramはただの夢物語の設計書から「明日、自宅PCに最初の一粒の種（コード）を植え、時間とともに何世代にもわたって自己進化・循環する、極めて物理的で強靭な知能の森」へと、完全かつ確実にその歩みを進めることができる。
