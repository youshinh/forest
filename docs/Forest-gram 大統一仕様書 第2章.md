# **Forest-gram（フォレスト・グラム）大統一システム仕様書**

## **第2章：植物学的対称マッピングと生理学（Botanical-Software Symmetry）**

## **2.1 部位別対称マッピング（Botanical-Software Anatomy）**

Forest-gramを構成するすべてのソフトウェアエージェント、プロトコル、およびデータ構造は、実在する樹木の解剖学的部位と1対1で対応（対称マッピング）する。これにより、結合カオス（エントロピー増大）に抗う強靭な「知能の自己組織化」を可能にする。

### **2.1.1 根（Roots）：MCP（Model Context Protocol）による物理・OS低レイヤー操作**

樹木の「根」は、土壌（ホストPC環境）に深く根を張り、安定して自立を支えるとともに、無機養分や水分（ファイル、データベース、APIリソース）を吸い上げる物理的な触手である。

* **システム実体：** エージェントが使用する「MCP（Model Context Protocol）ツール」および「OSシステム操作権限」。  
* **動作仕様：**  
  * 各樹木エージェントは、固有の「根の長さ（アクセス制限：Scope）」を持つ。例えば、フロントエンドを担当する cherry の根は projects/{project\_id}/deliverables/ 領域にのみ制限され、低レイヤーのデバイス制御を担当する teak の根は、ホストPCのシリアルポートやローカルデータベース（SQLite）などのシステム深部へ深く潜入できる。  
  * 根からの吸い上げ（ファイルの読み込みやコマンドの実行）は、すべてセキュアなサンドボックスプロセス（制限された非特権ユーザープロセス）を経由することで、エージェントがホストOSの重要なシステム領域を破壊する（根腐れ・土壌汚染を起こす）リスクを物理的にゼロにする。

### **2.1.2 幹（Trunk）：エージェント基本骨格（agent.md）と年輪（Gitコミット履歴）**

樹木の「幹」は、木化（Lignification）によって頑丈に硬化した強固な中心軸であり、地表から空へ向かって葉（LLMインスタンス）を空間展開するための「構造的支持構造」である。また、内部の道管・師管を通じてすべての養分（情報・コンテキスト）を輸送する。

* **システム実体：** エージェントの基本設定ファイルである agent.md 、 skills\_agent.md 、およびそれらの「Gitコミットバージョン履歴」。  
* **動作仕様：**  
  * **年輪（Annular Ring）：** 樹木が毎年、季節の寒暖（現実のプロジェクトの成功・失敗の摩擦）を経て「年輪」を重ねるように、エージェントの agent.md には、蓄積された反省（Post-mortem）によるアップデート履歴が、Gitのコミット履歴（Diff）として「年輪」の如く永続的に刻まれる。  
  * ユーザーは、Git履歴を遡ることで、その樹木がどのようなエラーというストレスに適応して強固な「芯材（心材）」を獲得したかを完全に追跡・マッピングできる。

### **2.1.3 枝（Branches）：並行・並列処理トポロジー（タスクの自動分岐）**

樹木の「枝」は、1本の幹から効率よく空間へ分散し、無駄なく光（ユーザー要求）を浴びるために展開される。

* **システム実体：** SUN Agent（PM）によって解析されたタスク（チケット）の「並行・並列処理トポロジー（有向非巡回グラフ：DAG）」。  
* **動作仕様：**  
  * プロジェクト全体の要求を解決するため、複数のサブタスクが並行して展開される際、これを「枝分かれ（Branching）」として物理フォルダ展開する。  
  * **トポロジカルソート（依存関係順序制御）：** 枝は「太い枝（親タスク）」からしか「細い枝（子タスク）」が生えない。この依存構造はGraphQLスキーマによってマッピングされ、前提タスクが完了（パス）するまで、従属する子タスクのチケット（新枝）は環境の掲示板（Board）へアンロック（公開）されない。

### **2.1.4 葉（Leaves）：LLM推論インスタンスおよび動的ピクセルアート描画**

樹木の「葉」は、光（ユーザーのプロンプト入力やフィードバック）を受け取り、炭酸同化作用（LLM推論によるテキスト・成果物の生成）によって smile エネルギー（デンプン）を動的に生産する代謝の最前線である。

* **システム実体：** 各樹木エージェントが、チケットをPullした瞬間に立ち上げる「LLMコンテキストウィンドウの推論空間（推論インスタンス）」、およびユーザーのブラウザ上にリアルタイムでレンダリングされる「8bitドット絵アニメーションアバター」。  
* **動作仕様：**  
  * 葉は常に風（システム負荷やエラー）に揺れ、外界との直接的な相互作用を行う。  
  * 葉の健康状態（ヘルス）は、色やスプライトアニメーションで表される。自動テストに合格し、多くの smile を生成している状態は「青々とした新緑」として描画され、エラーが多発している状態は「葉の虫食い（Infestation）」や「変色」として描画される。

### **2.1.5 菌糸（Mycorrhiza）：Forest-Commons（共有知）を介した地下ネットワーク**

現実の森林において、異なる樹木同士は単独で孤立しているのではなく、地下を網の目のように覆う「菌根菌（マイコライザ）」の菌糸ネットワークを通じて相互に繋がり、水分やリンなどの栄養、さらには「害虫襲来の警告（化学シグナル）」を伝え合っている。

* **システム実体：** エージェント間で共有される知識の共有地 forest\_commons/ （RAG用ローカルベクトルデータベースおよびMarkdownテンプレート群）。  
* **動作仕様：**  
  * 例えば、maple エージェントが直面し、苦労してデバッグ・反省した「ライブラリ競合による致命的エラー」の解決ロジックは、菌糸ネットワーク（forest\_commons/fail\_patterns/）へ即座に放出される。  
  * walnut や cherry といった他の個体は、自身のフォルダと菌糸ネットワークが物理的に結合しているため、直接の対話（通信）を経由せずとも、次に類似タスクをPullした際に「隣人が得た痛みと解決策」を自律的に吸い上げ、先回りしてエラーを回避（予防保守）する。

### **2.1.6 種・実（Seeds/Fruits）：シリアライズされた遺伝子情報（GraphQL / JSON）**

樹木は自らの最良のパラメータ、培ったスキルを未来に託すため、遺伝情報をパッケージ化した「種（Seed）」を形成する。

* **システム実体：** 交配（Crossover）時に親から子へ引き継がれる「スキルID配列」および「初期能力パラメータ（DNA）」を記述したGraphQL/JSONメタデータ。  
* **動作仕様：**  
  * 親エージェントが蓄積した smile を支払うことで、「種」が生成される。この種は環境内に一度プール（保存）され、次の要件定義フェーズにおいて、サンドボックスでの「芽吹き（Initialization）」を経て新しい樹木エージェントとしてギルド（環境）に誕生する。

## **2.2 システム生理機能の極限設計（Botanical-Software Physiology）**

樹木の持つ驚異的な自己制御ループ（生理機能）を、ソフトウェアリソース（CPU/VRAM/ファイルシステム）の保護機能として第一原理からコードレス仕様化する。

### **2.2.1 剪定（Pruning / 枝打ち）仕様：暴走プロセスの自動強制終了（Kill）**

植物が陽の当たらない非効率な葉や枝を自ら枯死させる、あるいは人間が「枝打ち」をして主幹の成長を最適化するように、システムもリソースを浪費する「肥大化したプロセス（枝）」を自律的に剪定しなければならない。

* **トリガー条件：**  
  1. 専門エージェントがタスク実行中に無限ループに陥った場合（実行時間 T\_{run} \> 60 秒）。  
  2. 生成された一時キャッシュファイル（temporary/ 領域）が急激に異常肥大化した場合（サイズ S\_{temp} \> 1 GB）。  
  3. 仕掛品（WIP: Work-In-Progress）の上限を超えて並列タスクが同時乱立しようとした場合。  
* **動作仕様：**  
  * SUN Agent（PM）、または環境監視デーモン（ホストOSプロセス監視）が、異常な枝（スレッドID/プロセスID）を検出する。  
  * 環境は「剪定（Pruning）」コマンドを無慈悲に実行し、該当のプロセスを物理的に **強制終了（SIGKILL / OSレベルのプロセス切除）** する。  
  * 剪定後、残された残骸（部分的ログ）は「2.2.3 菌類分解処理」に回され、メインの幹（システム全体の安定）は完全に保護される。

### **2.2.2 落葉（Defoliation / スリープ）仕様：VRAM・メモリの完全解放**

落葉樹が冬期、極端な乾燥や低温から水分（計算リソース）の浪費を防ぐために、全ての葉を自ら落として代謝を落とし休眠するように、Forest-gramにおけるLLM接続プロセスもリソースの「落葉（完全クレンジング）」を実行する。

* **トリガー条件：**  
  * クエストが完了（または一時凍結）し、プロジェクトに動きがないアイドル時間が10分以上継続した場合。  
* **動作仕様：**  
  * エージェントは、LLM推論時に確保していた長大なコンテキストキャッシュ（K-Vキャッシュ）、およびメモリ空間を物理的に破棄（デストラクト）する。  
  * ローカルホストサーバー（Ollama / vLLM）に対し、エージェントモデルの\*\*「VRAMからの完全アンロード（Unload Model from Video Memory）」\*\*シグナルを送信する。  
  * これにより、グラフィックボード（GPU）のVRAMは完全に 0 GB に近づき、ホストマシンは他の物理処理（木材CNC制御、3Dプリンター処理など）のために計算リソースを100%解放した、極めて健全な「大地（Soil）」の状態へ自律復帰する。

### **2.2.3 木化（Lignification / 堅牢化）仕様：プロダクトコードの不変凍結**

木材の最大の特徴は、新芽のような柔らかく変化しやすい細胞が、時間が経つにつれて「リグニン」が沈着し、カチカチに硬化した「木質（木材）」へと変化することである。木化された部分は二度と伸縮や形状変化（バグの混入）にさらされず、幹として全体の重量を何十年も支え続ける。

* **トリガー条件：**  
  1. 生成された特定の成果物コード（deliverables/ 領域の関数やモジュール）が、自動CI/CDコンパイル＆テスト（客観評価）を3回連続で完全一発クリア。  
  2. かつ、ユーザーからの主観評価において、星5（大絶賛）を獲得。  
* **動作仕様：**  
  * システムは、該当のコードファイルを\*\*「木化（Lignified）」\*\*とスタンプし、ファイルのパーミッションを **リードオンリー（chmod 444 / 読み取り専用）** に物理変更する。  
  * 以後のタスク開発において、他のエージェント（新規世代の樹木たち）は、このコードを「インポートして参照（再利用）する」ことのみが許可され、**直接エディット（書き換え・改変）することはシステムレベルで完全に禁止（ガード）** される。  
  * これにより、一度完璧に動作した資産が、後発の未熟なエージェントによる「リファクタリングの失敗」という致命的ハルシネーションで破壊される（先祖帰りバグ）のを防ぐ、究極の信頼の骨格を構築する。

### **2.2.4 土壌と水分（Soil & Water）の物理境界制限**

樹木が育つための「土壌（計算ストレージ）」と「水分（VRAM/CPU能力）」は有限であり、これらの枯渇は生態系全体に「ストレス（状態異常）」を発生させる。

* **水分量（VRAM/RAMの空き容量）：**  
  * システムは常にOSのメモリ圧迫率（物理ストレス）を監視する。  
  * メモリ空き容量が15%を下回ると「干ばつ（Drought）」デバフが森林全体に発令され、全エージェントは高度なモデル（消費トークン量の多い大型LLM）から、極小のローカルSLM（小型言語モデル：例: Gemma 2B等）への強制切り替えを行い、処理をスリム化して生存を図る。  
* **土壌品質（ストレージ空き容量 ＆ ゴミファイル蓄積度）：**  
  * プロジェクトディレクトリ内に、Git追跡対象外のゴミファイル（キャッシュやビルド不適合の中間ファイル）が蓄積すると「土壌汚染（Soil Contamination）」が発生する。  
  * 汚染度が限界値に達すると、自動的に「5Sクレンジングプロセス」が地下で起動し、古い temporary/ 領域を強制5Sクレンジング（完全削除）し、豊かな黒土（クリーンな物理ディスク）を自律的に維持する。

本第2章で定義された生理作用の自律トリガーは、デジタルの混沌に、秩序ある「物理の硬さ、木工の構造美」をもたらし、エントロピーを自律的に削ぎ落とす。
